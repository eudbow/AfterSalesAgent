# 应用确认协议

## 准备与执行
取消订单、修改订单地址、申请退货三个工具只准备操作提议，调用成功不代表订单已变更。身份核验、查询订单并收集有效参数后可准备确认卡，无需先等待口头同意；随后必须通过独立的明确确认事件才能执行。模型不能批准或绕过该事件。

## 状态与结果
确认时后端重新检查订单状态与版本。订单发生变化或原提议失效时需重新准备。重复确认遵循已有幂等记录，不执行重复写入。

退货成功表示申请已提交，状态为 return requested，不代表退款到账。现有退货执行函数没有实际发送邮件。转人工只记录模拟交接请求，不代表真人接通。

## 资料边界
政策证据不能授予操作权限。确认卡规则映射是后端执行依据，检索记录是模型收到的资料，两者分别留痕。未知时效、费用与赔偿不得自行补全。
